# 功能说明

SIMHarbor 将双卡的短信、来电、状态与通知集中到一个管理台，既能在家中使用，也能部署到自己的云服务器。

## 短信与卡身份

收件箱支持按正文或发件号码搜索、按卡筛选、未读/已读、详情查看和单条删除。长短信按分片组装，页面展示完成状态，方便识别完整内容与待补齐的记录。需要归档时，可以导出收件短信 JSON 或 CSV；来电、发件与其他业务数据随完整数据库备份保存，见[数据维护](data-maintenance.md#选择导出或备份)。

分片进度只用于长短信。普通短短信不显示进度；即使板子携带组信息，只要明确总数为 1，也不显示“1/1”。长短信列表显示“等待分片 · 1/3”或“已收齐 · 3/3”，详情列出已保存和缺失的分片序号。重复上报不会重复计数；板子直接报告完整正文时，以其完整标记确认收齐。只有正文、没有分片序号时不猜测已收片数；旧记录未保存总片数时明确显示未知。页面进度用于观察已保存状态，不会主动补取缺片。

旧的完整聚合记录若连组信息和分片序号也未保存，应用无法再区分长短信与普通短信，保持原有完整短信显示。有分片但总数未知的旧记录只显示已保存片数；只有后续真实上报匹配同条业务记录时，才能补充总数并继续组装。

卡目录通过固定身份关联历史，展示卡名（板子备注）、号码、完整卡 ID 和当前位置。卡 ID 是应用为该 SIM 身份保存的固定标识，也是短信与来电筛选使用的值，不是原始 ICCID；名称、号码和卡槽变化不会改变它。换槽后仍能按原卡查看短信与来电；改名后的新记录使用新名称，旧记录保留当时的名称快照。身份信息暂缺时会明确标为未知，便于后续核对。

卡名和号码在状态查询确认同一卡身份后，用非空的新值分别更新，不是只在首次读取时保存。缺少字段或返回空值时，保留已有资料；短信与来电上报中的名称可补齐空白卡名，不用可能延迟的业务上报覆盖已保存名称。首页在当前卡身份确认后补用保存资料，并标注来源。短信与来电缺少当时的名称快照时，按固定卡身份匹配已保存的卡名，标注“自动识别”；这表示应用匹配了卡记录，不表示板子在收件时上报了该名称。原始历史与导出中的名称快照保持不变。注册网络仍以板子当前上报为准。

名称回退作用于页面显示，已发送的 Bark 通知及任务中的原名称快照不回填。以后卡记录改名时，缺少快照的历史条目随保存名称变化，已有名称快照的条目仍展示原名。旧版已丢失且板子未重新报告的名称或号码无法由升级自动恢复；无法确认卡身份时也不按卡槽或注册网络猜测。

删除短信会清除应用中对应的正文、号码和分片，并保留去重删除标记。板子本地存储、备份与手机通知各自管理，便于按自己的数据保留计划维护。

## 来电记录

集中查看来电号码或匿名标识、开始/结束时间、已确认的响铃信息和所属卡片。同号码记录可展开回看，适合追踪多次来电。

未接提醒结合来电过程信息生成：收到结束信息后判定；有效开始上报满 5 分钟且未收到结束、接通或冲突信息时，会提示“曾来电，结束时间未确认”，帮助你留意信息尚待核对的来电。此提示记录的是上报情况，实际接通与费用以运营商记录为准。语音接听由板子及运营商侧处理，管理台负责记录与提醒。

留言是单独开启的能力，默认关闭，并与“只提醒、不接听”互斥。开启后由板子按预先下发的参数自动接听并录音；接通后 Harbor 发送一次提示音。应用在本地部署接收板子上传的 AMR。来电记录可在网页中播放这段录音，也可下载原始文件。云端部署仍管理短信和来电，这一阶段不接收录音。操作、费用和关闭方法见[留言](voicemail.md)。

## Bark 通知

在系统配置中填入自己的 Key 和服务地址，保存并在网页确认重启应用后，即可在“通知诊断”发送连接测试。测试直接通过 Bark 完成，免用 SIM 短信；每分钟可测试一次，结果待定时查询原任务。

- **按卡分组**：完整短信生成通知任务，标题使用收件时卡名，分组关联固定卡身份。
- **随手开关**：每张卡可独立设置短信与来电提醒，收件照常保存；重新开启后接收后续新业务通知。
- **持久重试**：失败任务保存到数据库并退避重试，符合条件时可确认提前重试。
- **直达详情**：通知链接打开对应短信或来电记录。
- **进度可查**：分别展示待推送、重试和 Bark 接受情况，今日/近 30 天统计按首次接受时间计算，连接测试单独记录。

“推送成功”表示 Bark 服务端已接受请求，是通知任务的成功最终态。成功任务只在此前发生过失败时显示失败次数。手机到达情况可结合 Bark 权限与网络核对。网络响应丢失后的重试可能产生重复通知，诊断页可帮助追踪原任务。

## 状态与提醒

首页展示当前连接、最近上报、信号与两卡注册状态，并标注状态新鲜度。“查询板子状态”可主动查询板子，方便在配置后或排障时核对。

持续异常提醒采用观察窗口，减少短暂波动带来的打扰：

| 事件 | 提醒条件 |
| --- | --- |
| 板子离线 | 连续观察 15 分钟 |
| 单卡异常 | 连续观察 30 分钟，结合有效来源及当前板子状态判定 |
| 恢复正常 | 异常提醒已被接受后，连续确认正常 5 分钟 |

应用重启后重新累计观察时长。保持应用与 Bark 服务可用即可持续观察；主机自身的可用性可搭配外部监控管理。

## 板子设置

通过管理台查询板子状态、本地短信/通话历史和存储开关，读取心跳间隔，并按“读取 → 预览 → 确认 → 读回”流程调整心跳。同一流程可下发留言的上传地址和来电方式：上传地址走 TCP，来电方式在固件拒绝 TCP 时改由短信指令写入。控制短信走与外发相同的卡身份、本机号码、费用确认和限额，并且与普通外发计入同一张卡的间隔和每日额度；没有控制短信回报时只记为已提交，不把目标来电方式当成已读回，也不自动重发。同一目标在没有相反操作之前不会再次发送。提示音不在这次确认里下发，接通后由 Harbor 发送。敏感身份默认隐藏，便于日常查看与诊断。

本地历史按物理卡槽展示，与应用中按固定卡身份整理的收件箱分别查看。查询保留板子原记录状态，应用收件箱、通知和已读状态保持原样。WiFi、TCP 目标及来电策略等原厂参数的配置方法见[板子配置](hardware-setup.md)。

## 短信外发

短信外发默认关闭，可在系统配置中按需启用并重启应用生效。每次发送先预览正文与段数，再核对目标、重新输入号码并确认，帮助管理发送内容与费用。

服务下发前会再次核对卡身份、发送间隔和每日限额，并先持久记录操作。网络断开、超时或重启后，可继续查询原操作；结果未知时保留核对空间，避免自动重发带来的费用。完整发送历史支持相同内容的防重复检查。

发件箱分别记录板子接受、提交运营商及匹配到的送达报告，方便追踪各阶段；最终送达以完整匹配的报告或收件方确认为准，段数估算供发送前参考，实际计费以套餐为准。

迁移恢复后，可通过[迁移确认](data-maintenance.md#迁移确认后恢复外发)核对历史并恢复外发；系统开关与逐条确认继续共同管理发送。外发以逐条人工确认为操作方式。
