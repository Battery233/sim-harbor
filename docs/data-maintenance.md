# 数据导出、备份与迁移

从日常归档到本地/云端迁移，SIMHarbor 提供短信导出、一致备份、完整性检查和受控恢复，让数据随自己的部署选择流转。

本文以 v1.1.6 为准，镜像使用方式见[版本维护](releases.md)。本版与 v1.1.2～v1.1.5 同为 schema 21，支持格式 1 和含录音的格式 2 ZIP，升级无需新增迁移或补填配置。v1.1.1 使用 schema 20、格式 1 ZIP，首次升级到当前版会自动迁移；v1.1.1 及更早程序不能直接打开新库，回退需使用兼容的升级前数据库。恢复会清除旧等待截止时间并暂停旧任务，避免补推历史来电。

## 选择导出或备份

| 你的目的 | 使用入口 | 保存内容 |
| --- | --- | --- |
| 阅读、表格整理或归档收件短信 | 短信导出：JSON / CSV | 筛选后的收件短信及卡身份、时间、完整性和已读状态 |
| 升级、恢复或迁移业务数据库 | 数据库备份：ZIP | 收件、发件与结果、来电、卡资料与通知偏好、通知任务、设备状态、恢复确认、留言索引、播放状态及控制短信账本；可勾选包含录音文件 |
| 同时保留留言录音 | 数据库备份勾选“同时备份通话录音” | 数据库与应用 `voicemail/` 内已关联、未关联的完整 AMR；也可单独私密复制该目录 |
| 转移访问凭据和部署参数 | 单独私密备份配置 | `.env`、初始化 JSON、私有 Compose 及数据目录内 `system.private.json` |

通话记录与发件箱随 ZIP 完整保存、恢复；JSON/CSV 入口用于收件短信。升级前在网页选择“数据库备份”，生成并下载，或保存到服务器后另行下载。

## 短信导出

在“数据维护”选择卡身份、号码和日期范围，下载匹配的收件短信 JSON 或 CSV。日期使用浏览器本地时间，开始时间包含、结束时间不含；发件号码按精确匹配筛选。JSON 保留原文，CSV 对公式样式文本加保护前缀；导出保留原有已读状态与任务状态，适合独立归档。

单次支持最多 10,000 条 / 32 MiB；较大范围可按日期分批导出，保证每个文件完整。JSON 使用 `format_version=2`，包含筛选条件与记录；包含长短信进度的维护版为记录增加 `multipart`、`parts_total`、`parts_received`、`part_indices` 字段，总片数为 0 表示未知。CSV 沿用原列，不增加分片元数据。两种导出均保留原名称快照，不填入页面补用的已保存名称；导出包含私人内容，请妥善保存。

## 一致备份

在“数据维护 → 数据库备份”选择保存方式并勾选私人数据保管确认：

- **下载到浏览器**（默认）：服务器先生成 ZIP，再下载到电脑。支持文件选择器的浏览器可直接流式写入所选文件，其他浏览器收齐文件后交给普通下载；超过 256 MiB 时需使用支持文件选择器直接写入的浏览器，避免占满内存。服务器临时副本保留 1 小时，下载中断可在列表重新下载同一份文件。
- **保存到服务器**：后台生成后长期保留，页面关闭不影响任务。可从列表查看时间、大小和 SHA-256，下载或单独确认删除。它与应用在同一台机器上，重要备份应再下载另存。

应用通过 SQLite Online Backup API 取得包含业务库与 manifest 的一致快照，日常运行中即可完成备份，并纳入 WAL 中的有效数据。两种保存方式都可勾选“同时备份通话录音”，默认不勾选。

- **未勾选**：ZIP 格式 1，只有数据库与 manifest；包含录音索引，不含 AMR 文件。
- **已勾选**：ZIP 格式 2，增加 `voicemail/<录音ID>.amr` 和每个文件的大小、SHA-256。包含已关联、未关联及目录内未入库的完整、命名合规 AMR；排除上传临时文件与已登记删除的文件。

含录音快照与上传、删除共用文件协调机制，取得数据库快照时固定对应文件；之后删除原录音不影响该快照。索引对应文件缺失、大小或摘要不符、AMR 头损坏、符号链接或读取错误时整次备份失败，不生成一份静默缺文件的备份。未入库文件随目录保存，但恢复不会伪造其通话关联。

### 文件位置与命名

网页备份位于 `<data_directory>/backups/<备份ID>/`，目录权限为 `0700`、文件为 `0600`；Docker 中该目录位于现有数据卷内，显示的是容器路径，不会自动保存到 Compose 所在的宿主目录。ZIP 名称为 `sim-backup-YYYYMMDDTHHMMSSZ-<备份ID>.zip`，使用 UTC 时间和随机标识避免重名；包内 manifest 另有 `created_at`。

此目录不通过静态网页公开，列表、下载、生成和删除都使用管理鉴权。应用只接受备份 ID，不接受网页指定任意服务器路径。目录内的 `metadata.json` 与 `.job.private.json` 是备份管理记录，不属于 ZIP 内容，不要手工修改或单独移动它们。

### 中断、清理与容量

- 同时只生成一份备份，生成超时为 10 分钟；提交结果不明时先刷新任务与文件列表，不自动重发。关闭页面只停止本页下载，后台生成继续。
- ZIP 与元数据完整写入并同步磁盘后才发布到列表。生成失败或正常关机中断会清理临时目录；异常退出后，在下次应用启动时清理自有未完成目录并恢复任务状态。已完成的 ZIP 保留，任务不会自动重新生成。
- 下载最多并行 2 份，每次最多 10 分钟。不支持字节断点续传；中断后重新下载现有文件，无需重新备份。下载中的文件不会因到期或删除操作被清理。支持直接写入文件时，失败下载会撤销临时写入；普通下载必须收齐声明长度才交给浏览器。
- 单份备份的文件或管理信息无法读取、大小不符，或下载校验失败时，该项显示为“不可用”，正常备份仍可查看和下载。不可用项保留原文件、不自动过期清理，仍占用份数和可确认的容量；可核对后在列表明确确认删除整项备份。若占用无法确认，暂停生成新备份，避免低估容量。备份根目录或全局任务管理文件异常仍需先排查权限与文件完整性。
- 浏览器临时副本从生成完成起保留 1 小时，到期后由应用定时或刷新列表时清理；应用停机时不执行清理，下一次启动再处理。服务器长期备份只由操作者确认删除，不按时间自动清理。
- 服务器 ZIP 总容量默认 **2048 MiB**，最多 **20 份**（含临时副本）。可在“系统配置 → 服务器本地备份”修改 `backup_max_storage_mib`，`0` 或缺省使用默认值，显式范围为 544～65536 MiB，保存并重启应用后生效。降低上限不会删除已有文件，超过限制时拒绝新增。
- 开始前检查容量和剩余磁盘空间；生成时数据库快照与 ZIP 同时存在，需要额外临时空间。检查不能阻止其他进程消耗磁盘，实际写入不足仍会失败并清理本次临时文件，保留旧备份。清理或权限错误会显示失败，需核对目录，不能把临时文件当作已完成备份。

完成服务器保存，或完整传输当前浏览器备份后，才可作为本次迁移确认的备份依据；应用重启、发送历史变化等仍会使确认失效。删除或发现作为确认依据的服务器文件损坏时，该依据也会失效，需重新保存当前备份。

ZIP 内含 `sim.db` 与 `manifest.json`；manifest 记录数据库摘要、版本和各类记录数量，便于恢复前核对。

单份备份的数据库上限为 512 MiB；不含录音 ZIP 上限 544 MiB。含录音时每个 AMR 不超过 2 MiB，目录扫描最多 10,000 项（包含非 AMR 项），录音总字节另设 65,536 MiB 防护上限。这些限制同时生效，不表示一定可备份 64 GiB 录音；ZIP 还受服务器剩余备份配额与磁盘空间约束。录音快照固定文件、ZIP 和恢复校验副本都可能需要临时空间。`system.private.json`、环境变量和日志分别保存；完整迁移时一并私密备份配置与凭据。ZIP 未加密，SHA-256/CRC 用于完整性检查，保存建议见[安全说明](../SECURITY.md#私有数据与备份)。

## 检查与恢复：源码工具

当前维护工具支持格式 1、格式 2 和 schema 21，也可检查、恢复受支持的旧库。`backup` 与 `inspect` 不迁移原数据库；`restore` 校验所选 ZIP，在新目录迁移其数据库副本到当前 schema，原库与备份不变。沿用原数据目录升级应用则由首次启动迁移，已有迁移确认保留；两种操作不同。

| 应用版本 | 数据库 schema | 该版本生成的 ZIP |
| --- | --- | --- |
| v1.0.2 / v1.0.3 | 16 | 格式 1，数据库与 manifest |
| v1.0.4 | 17 | 格式 1，增加分片上报关联 |
| v1.1.0 | 19 | 格式 1，包含录音索引，不含 AMR |
| v1.1.1 | 20 | 格式 1，包含录音等待与通知阶段，不含 AMR |
| v1.1.2～v1.1.6 | 21 | 默认格式 1；勾选录音为格式 2，同时还原 AMR |

格式 1 只有录音索引，单独保存的 `voicemail/` 需放回新数据目录；没有文件时页面会提示缺失。格式 2 同时还原数据库、录音和播放状态，但不会为目录内未入库文件伪造关联。恢复还原的是备份时点：备份之后才删除的录音可能随旧快照恢复，不代表删除操作失败。

两种格式均保存数据库内已有的系统推送历史；恢复会暂停旧待发送任务并清除旧录音等待截止时间，不补推历史。容量提醒去重文件 `voicemail-capacity.private.json` 独立于 ZIP，需随私有资料保留。缺失该文件后，应用会按当前容量重新评估提醒。

旧版不能直接打开更高 schema，格式 2 也不能交给只支持格式 1 的旧工具。回退需兼容的升级前数据库、配置及容量提醒进度副本；不要手改 `schema_version`。逐版升级边界与候选版差异见[版本维护](releases.md#已有实例升级)。

在项目根目录使用与备份兼容的程序版本。先检查：

```sh
GOTOOLCHAIN=local go run ./cmd/maintain inspect -backup /private/path/sim-backup.zip
```

工具返回版本、数量、是否含录音、录音清单及 `archive_sha256`，以摘要形式完成核对。核对后恢复到**不存在的新目录**，将下面占位摘要替换为 inspect 返回值：

```sh
GOTOOLCHAIN=local go run ./cmd/maintain restore \
  -backup /private/path/sim-backup.zip \
  -to data/restored-instance \
  -confirm-archive REPLACE_WITH_ARCHIVE_SHA256
```

恢复到独立新目录后，原库与配置继续保留，便于比对与回退。再准备指向新目录的初始化配置：原生运行示例目标为 `data/restored-instance`，容器运行则使用卷内路径。恢复工具与备份版本应兼容，原始备份留存。

没有网页时，可停止占用该目录的应用，再执行停服备份。输出文件必须不存在：

```sh
GOTOOLCHAIN=local go run ./cmd/maintain backup \
  -data-directory data/instance \
  -output /private/path/sim-backup.zip
```

停服备份时加 `-include-recordings` 可生成含录音 ZIP；不加时沿用格式 1。`inspect` 和 `restore` 根据包内 manifest 自动识别，不需要该参数。恢复先校验整个 ZIP、数据库和录音，再写入全新目录；路径穿越、重复文件、符号链接、缺失文件或摘要不符均拒绝。恢复期间中断会保留 `.restore-incomplete` 标记，应用拒绝启动该目录；保留现场，另选新目录重试，不能删除标记后强行启动。

应用与维护工具共用进程锁，协调目录占用；保留 `.sim.lock` 和恢复标记，由工具完成检查与状态管理。

## Docker 维护工具

镜像内的工具为 `/app/sim-data`。以下假设采用[Docker 文档](deployment-docker.md)中的镜像和项目名，宿主私有备份目录 `/srv/sim-backups` 需自行创建、放入所选 ZIP，并让容器 UID 65532 可读。工具以非 root 运行，请按容器用户权限准备备份目录。

### 校验备份

以下为仅数据库 ZIP 的校验示例：工具在 `/data` 创建 ZIP 校验副本和解包文件，临时内存目录随容器退出释放。示例上限为 2 GiB，使用 tmpfs 还需主机有相应可用内存；它不会在启动时一次占满该上限。临时空间需同时容纳 ZIP 副本与解包后的数据库，不能只按 512 MiB 数据库上限配置。含录音包或内存不足时，按下文改用私有磁盘临时目录。先独立检查备份包：

```sh
docker run --rm --network none --read-only \
  --tmpfs /data:rw,uid=65532,gid=65532,mode=0700,size=2048m \
  --mount type=bind,src=/srv/sim-backups,dst=/backup,readonly \
  --entrypoint /app/sim-data sim-harbor:1.1.6 \
  inspect -backup /backup/sim-backup.zip
```

也可先准备空的宿主私有目录 `/srv/sim-maintain-tmp`，让容器 UID 65532 可写，并使用磁盘进行校验。该目录与 `/srv/sim-backups` 分开，不得指向在线数据目录：

```sh
docker run --rm --network none --read-only \
  --mount type=bind,src=/srv/sim-maintain-tmp,dst=/data \
  --mount type=bind,src=/srv/sim-backups,dst=/backup,readonly \
  --entrypoint /app/sim-data sim-harbor:1.1.6 \
  inspect -backup /backup/sim-backup.zip
```

镜像内 `TMPDIR=/data`，源码工具则使用系统临时目录；容量不足时可为该次源码命令指定自己的私有 `TMPDIR`。`inspect` 需要 ZIP 副本、解包文件及余量；`restore` 还需要迁移后的数据库快照与最终目标空间。检查空间与最终数据目录都必须足够，不能只按 ZIP 压缩大小估算。正常返回会清理本次临时目录；被强制终止或断电时可能留下 `sim-inspect-*`，核对没有维护进程使用后再按具体目录清理，不批量删除其他临时文件。

### 恢复到新目录

恢复到卷内新子目录。先核对实际卷名，下面的 `sim_sim-data` 对应安装指南中的 `-p sim`；自定义项目名时使用自己的卷名。先确认卷已存在、目标子目录不存在，再执行恢复：

```sh
docker volume inspect sim_sim-data --format '{{.Name}}'
```

```sh
docker run --rm --network none --read-only \
  --mount type=bind,src=/srv/sim-backups,dst=/backup,readonly \
  --mount type=volume,src=sim_sim-data,dst=/data \
  --entrypoint /app/sim-data sim-harbor:1.1.6 \
  restore -backup /backup/sim-backup.zip \
  -to /data/restored-instance \
  -confirm-archive REPLACE_WITH_ARCHIVE_SHA256
```

`/data/restored-instance` 是容器内路径，在 Docker 卷中，不是宿主同名目录。确认恢复完成后，在专用初始化配置中将 `data_directory` 指向此路径，单独设置对应私有凭据再启动。运行配置按目标部署方式单独准备。`restored-instance` 是便于说明的目录名，也可以使用尚不存在的 `/data/storage` 等自定义路径。

### 停服备份

网页暂时不可用或正式迁移需要最终快照时，可以用源实例对应版本的镜像执行停服备份。下面以 `sim-harbor:1.1.6`、数据目录 `/data` 为例；如果实际目录为 `/data/storage`，调整 `-data-directory`。宿主 `/srv/sim-backups` 需允许容器 UID 65532 写入，输出文件使用尚不存在的新名称。

先沿用原项目名及完整 Compose 文件停止应用；这里展示基础安装参数：

```sh
docker compose --env-file .env -p sim \
  -f compose.yaml -f deploy/site.private.yaml stop sim
```

确认应用已停止，再执行：

```sh
docker run --rm --network none --read-only \
  --mount type=volume,src=sim_sim-data,dst=/data \
  --mount type=bind,src=/srv/sim-backups,dst=/backup \
  --entrypoint /app/sim-data sim-harbor:1.1.6 \
  backup -data-directory /data -output /backup/sim-backup-final.zip
```

需要同时保存录音时，在上述 `backup` 命令末尾加 `-include-recordings`；不加仍生成只有数据库与索引的格式 1。备份完成后按上方 inspect 方法核对。普通维护可按原部署方式恢复服务；正式迁移则由目标实例接续接入。

## 恢复后的保护

恢复保留卡备注、固定身份、按卡通知偏好和历史，新到收件按正常配置处理。同时取消旧发送预览，保留待核对的外发结果，并将旧待通知任务置为 `restore_held`，让新实例从清晰的任务状态接续运行。新增外发在完成迁移确认后开放。

恢复保护用于在迁移后核对完整收费历史，避免重复发送。通过下方迁移确认流程解除，配置中的外发开关随后继续独立管理日常发送。

## 迁移确认后恢复外发

在“数据维护”完成历史核对、备份与确认，即可恢复外发能力。确认动作保存迁移记录，实际短信仍按逐条预览与确认流程发送。

1. 停止原实例继续外发，以后只由当前实例管理发送。
2. 核对原实例备份之后的完整发送尝试与结果。未知结果可能已产生费用，按原操作核对；历史尚待补齐时，先保留保护。
3. 在当前实例上方“数据库备份”生成一份新备份并完整下载，或成功保存到服务器；重要文件另存到独立存储，配置和凭据单独保存。
4. 在下方逐项确认“原实例已停止”“历史完整”“未知结果已核对”“备份已保存”，点击“预览恢复外发”。
5. 核对预览后，再勾选最终确认，点击“确认解除恢复保护”。核对完成后立即生效。
6. 页面读回已保存状态。若系统配置仍关闭外发，需单独开启、保存，再通过网页确认重启应用；之后每条短信仍需预览、费用和目标确认。

备份完成后有 15 分钟的确认窗口，一次性预览沿用同一截止时间，并与当前恢复身份、发送历史绑定。发送历史包括普通短信和用于板子设置的短信；新增设置短信尝试或更新其发送结果后，原备份与预览不再作为确认依据，需重新备份、预览。未确认结果计数也包含已认领或结果未知的设置短信，它们不会自动重发。重新备份会更新预览依据；应用重启或相关状态变化后重新备份、预览。确认响应待定时，重新读取已保存状态核对结果。

确认记录包含时间、备份摘要与策略，并保留原恢复来源。已有发送记录、限额、卡身份校验、待核对结果、已取消预览与 `restore_held` 通知均按原状态保留。每次从备份恢复，都会建立新的恢复身份并重新进入保护流程，便于按次核对迁移。

原实例停止与历史完整性由操作者核对并声明；应用校验当前实例的备份、预览与保存状态。整个流程沿用管理入口的身份和来源检查。

## 本地与云端迁移

1. 在目标主机准备镜像、访问入口和私有配置，确认网络、Bark、AES 与路径规划。可先用在线备份演练恢复与核对。
2. 正式切换时安排维护窗口，停止原实例接入，再使用停服备份取得最终一致 ZIP，保存对应配置与摘要。
3. 私密传输，在目标主机 inspect，核对摘要、版本、数量及是否包含录音后恢复到新目录；格式 1 的录音另行还原。目标配置指向该目录，初始化 JSON 与统一配置中的路径应一致。
4. 启动目标实例，登录核对历史、卡记录及推送开关，再将板子 TCP 目标切到新实例。
5. 核对当前状态、自然收件、通知与详情链接；维护窗口中的板子本地记录可按需查询核对。需要外发时完成迁移确认，再按需启用外发。
6. 由目标实例统一管理后续历史，原实例与最终备份作为私有核对副本保留。

两端数据各自保存，正式切换使用最终备份接续历史；回退前保存目标实例最新备份，并确认版本兼容性。备份保留生成时的数据，包括当时存在的短信，恢复时可结合自己的数据保留计划检查。
