# 故障排查

先记录发生时间、应用版本、部署方式和板子固件。从网页的当前状态、“运行诊断”和“推送记录”入手，反馈时使用脱敏摘要。

| 现象 | 先检查 |
| --- | --- |
| 容器健康但板子离线 | 应用与数据库已启动，继续核对板子 WiFi、TCP 目标、两层来源规则和 AES |
| TCP 端口能连接但无状态 | 网络已可达，继续检查设备编号、模式、Key/IV 与有效上报 |
| Cloudflare 502 | 从连接器所在网络检查回源地址和端口；独立容器的回环不是宿主；核对 IPv4/IPv6 |
| 401 或登录失效 | 区分 Access 登录与应用 Token，使用当前实例保存的凭据，不公开 Token |
| Bark 显示未配置 | 核对当前数据目录及生效的统一配置；只改 `.env` 不会覆盖旧 `system.private.json` |
| 显示推送成功但未看到 | 表示 Bark 已接受请求；在手机检查 Bark 通知权限、网络和显示设置，可用推送记录中的 Bark 连接测试核对链路 |
| 收件正常但某卡不推送 | 检查固定卡身份的通知开关、消息完整性和恢复暂停状态 |
| 已打开推送但旧消息没补发 | 开启只对后续新业务生效，不回放关闭期间或恢复暂停的任务 |
| 配置保存后仍旧值 | 查看“待重启生效”标记，保存后通过网页确认重启应用；确认读取的是当前实例/数据目录 |
| 换 IP 后板子失联 | 检查家宽出口是否改变，更新实际 TCP 来源规则；网页 Access 地址与此无关 |
| SIM 状态异常或灯闪烁 | 按实际型号核对电源、天线、接触、注册和网络；结合应用状态与原厂页面核对硬件和注册情况 |
| 恢复后提示阻止外发 | 属于持久恢复保护，参见[数据维护](data-maintenance.md#恢复后的保护) |
| 私有 JSON 读取失败 | 检查文件存在、绑定路径、0600 和容器 UID/宿主映射；按容器实际用户设置最小所需读取权限 |
| 已听到接通提示语，但没有录音 | 提示语经 TCP 下发，录音另走 HTTP/HTTPS；先看板子上传结果，再查“录音配置 → 未关联录音”与应用接收诊断，见下文 |
| 录音角标在升级后增加 | v1.1.2 不导入旧浏览器播放标记，历史录音起初按未播放计数；同一实例成功开始播放后才同步更新，下载不改变计数 |
| 含录音备份生成失败 | 核对录音索引对应文件是否缺失、损坏或不可读，以及配额和临时空间；该模式不会静默跳过坏文件，原备份保留 |
| 恢复后显示录音文件缺失 | 先核对 manifest 是否包含录音。格式 1 只有索引，需另行还原 AMR；格式 2 应由兼容工具一起恢复，不要只从 ZIP 取出数据库 |
| ZIP 下载提示浏览器不支持大文件 | 超过 256 MiB 需支持文件选择器直接写入的浏览器；可先选择保存到服务器，改用支持的浏览器下载，无需重新生成 |
| 某份备份显示不可用 | 其他正常备份仍可下载。先核对该项文件、管理信息和权限；原文件保留，删除需要在列表明确确认。占用无法确认时暂停新增备份，见[中断、清理与容量](data-maintenance.md#中断清理与容量) |
| 旧镜像启动报数据库版本不支持 | 当前库可能已迁至 schema 21；停止尝试降级，不手改版本字段，按[回退说明](releases.md#回退)准备兼容副本 |

## Docker 只读检查

在自己的项目根目录，沿用安装时的项目名和文件。下面是基础安装示例；升级时增加了 `deploy/release.private.yaml` 的实例，终端检查也携带该文件，自定义项目名与覆盖文件按实际替换：

```sh
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml ps
docker compose --env-file .env -p sim -f compose.yaml -f deploy/site.private.yaml logs --since 15m --tail 100 sim
```

按所需时间截取日志，在本机审阅并脱敏后分享错误摘要。`docker inspect`、展开后的 Compose 配置和 `.env` 可能包含凭据，作为私有运维资料保存。

应用日志位于业务数据目录的 `logs/`，容器正常部署为 `/data/logs/`；使用恢复子目录时随数据目录变化。网页诊断下载只包含有限的近期记录，保留容量和时间见[配置说明](configuration.md#日志保留)。

## 源码拉取与版本发布

| 现象 | 处理方式 |
| --- | --- |
| HTTPS 拉取/推送停在 Password 提示 | 使用自己的 GitHub Personal Access Token；终端输入凭据不回显字符。也可沿用已配置的 SSH 认证，见 [GitHub 认证说明](https://docs.github.com/en/get-started/git-basics/why-is-git-always-asking-for-my-credentials) |
| 本地能看到标签，GitHub 没有 | 核对标签指向，再单独推送该标签；分支与标签分别同步 |
| GitHub 没有 Release | 在 Releases 页面基于已有标签创建；操作顺序见[维护者发布指南](publishing.md#标签release-与镜像的关系) |
| Packages 中没有镜像或拉取失败 | 核对 Actions 的 Release image 结果、镜像标签、目标架构与包可见性；源码本机构建可独立使用 |
| 更新后出现空白历史库 | 核对 Compose 项目名、实际卷与 `data_directory`，保留原卷和备份，按原参数恢复接入 |
| 移动数据目录后启动失败 | 核对初始化 JSON 与新目录内 `system.private.json` 的 `data_directory` 一致，文件所有者和权限保持正确 |

## 按链路定位

以最近有效上报判断当前状态，并结合板子本地历史核对收件。应用收件箱保存已收到的固件上报，板子历史可单独查询。网络恢复后先查询原任务结果，再决定后续操作，保留清晰的发送与维护记录。

### 录音上传与关联

1. 核对“录音配置”的当前生效设置。保存待重启不等于接收已经开启；板子自动接听也不会随应用开关自动停止。
2. 上传地址可通过 TCP 读取；接听方式与板子预设提示语显示“需在板子后台核对”时，到 `/mgr` 查看，不为消除提示反复发送设置短信。听到 Harbor 的接通提示语只证明本次 TCP 播放链路生效。
3. 板子若提示连接上传主机的 443 端口失败，应先排查板子 DNS、网络、TLS/证书和边缘入口，不能仅据此归因于录音时长或应用容量。HTTP 请求尚未到达应用时，应用可能没有对应接收诊断。
4. 已返回 HTTP 响应时，区分错误类别：`voicemail_source_rejected` 为来源规则，`voicemail_upload_rejected` 为路径令牌，`voicemail_media_rejected` 为文件或参数，`429` 为限流/并发，`507` 为容量或数量上限。关闭接收返回 404；完整错误规则见[公网接收](voicemail.md#公网录音接收)。不要用管理根路径 404 当作上传成功。
5. 局域网模式检查已启用的设备来源白名单；公网模式检查应用实际看到的代理单 IP，不能通过放大 TCP 白名单修复。代理回源应保留路径、查询参数和文件，不要求板子完成 Access 邮箱登录。
6. 上传保存成功但来电里没有录音时，查“未关联录音”。卡槽、开始时间或来电标识不足、多候选时不会猜测关联；匿名仅支持唯一精确匹配，不使用时间容差兜底。已接通并确认结束、启用留言的新来电，3 分钟仍未关联会生成缺失提醒，迟到关联后再按[留言规则](voicemail.md#行为)处理。

反馈只提供时间、卡槽、错误代码和脱敏结果；完整上传地址包含授权令牌，查询参数还可能包含来电信息。

### 长短信一直等待分片

1. 在“数据维护 → 板子本地存储”中查询对应卡槽的本地短信历史，与应用记录的时间和完整性对比。历史查询只展示板子保存的内容，不包含长短信完整性及分片元数据；两边都缺少后半段时仍需继续定位。
2. 核对应用中相关记录的完整状态、已保存分片序号，以及是否出现同卡、同发送方、时间接近的多条记录。刷新页面只读取云端记录，不会主动补取缺片。
3. 在运行诊断中选择“短信收发”，查看收到长短信上报及后续入库结果，在技术详情中核对总片数、分片序号、短信时间和匿名组引用。同组引用可作为关联摘要筛选。板子报告未收齐、应用入库后已收齐，表示应用已合并此前保存的分片。
4. 将诊断接收时间与板子短信时间分别核对，留意总片数不一致、分片冲突、协议解析失败、事件入库失败和连接中断。默认日志不保存短信正文及原始报文，容量或级别限制也可能影响留存，没有诊断记录不代表设备从未上报。
5. 如需进一步定位，只提供时间、卡槽、应用记录编号、分片序号与错误代码等脱敏摘要。v1.0.1 的业务库没有单独保存组引用和总片数，升级后旧记录仍可能未知，无法仅凭旧库还原全部协议字段；不要直接修改完整标记或重放生产短信。

此诊断沿用现有日志级别与保留上限。配置为 `warn` 或 `error` 时不会保留信息级别的接收/成功记录，`error` 也会过滤分片拒绝的警告；应用不会自动调整日志配置。业务数据库保存分片进度，运行日志另行轮转，两者的留存范围不同。

需要进一步协助时，提交脱敏的复现步骤和错误摘要，区分“网页可达”“TCP 可达”“有效状态”“收件入库”“Bark 接受”和“手机实际到达”。
