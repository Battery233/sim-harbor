# 留言

留言默认关闭。在“录音配置”页依次准备应用接收、核对板子设置，两步分别确认：

| 设置位置 | 控制什么 | 何时生效 |
| --- | --- | --- |
| 录音配置 → 应用接收与提示语 | 接通后播放提示语，接收和保存录音 | 保存并重启应用后 |
| 录音配置 → 板子接听与上传 | 板子是否自动接听、录音，以及向哪里上传 | 确认执行后，以板子返回的结果为准；显示待确认时不能认定已生效 |

上传地址只在第一步编辑。第二步展示板子通过 TCP `askamrurl` 返回的地址和应用当前接收地址，隐藏路径令牌及查询参数，并按完整地址核对是否一致；“未设置”表示读回为空，不表示 TCP 无法查询。接听模式或板子预设提示语不能通过 TCP 读回时，分别显示未确认，不影响上传地址查询。开启会同步应用当前已生效的地址，停用会清空整块板子共用的上传地址。

应用设置未保存、尚待重启或保存结果不确定时，不允许启用板子。录音配置和系统配置分别保存各自的设置；发生版本冲突时，重新读取后再保存。重启会使所有已保存的应用配置生效，不只本页。

已有 v1.1.0 / v1.1.1-rc.1 配置可直接沿用；页面移动不会生成新地址或令牌，也不会自动向板子下发配置。生成模板只在地址为空时提供，仍需操作者补全局域网主机地址。

首次开启时，先在录音配置填写应用选项，保存并重启应用，再在同页读取并确认板子设置。录音上传后，应用只在能唯一对应来电时关联，并发送 Bark「有留言」。

关闭应用留言服务并重启后，应用不再播放提示语或接收新录音，已有录音保留。板子仍可能接听、录音和尝试上传，应用会拒绝新的上传。要彻底停用，还需在“录音配置”的第二步停止自动接听，并清除板子提示语和上传地址。

录音上传只在本地部署使用。云端部署继续管理短信、来电和通知，这一阶段不接收板子录音，也不要把云端网页地址当成上传地址。

云端录音支持和包含录音文件的备份列入[开发规划](roadmap.md)，均待开发、未排期。

这条路径与“只提醒、不接听”互斥。自动接听可能产生通话费用，录音时长以板子固件默认为准。

## 行为

| 状态 | 来电上报 | 板子 | Bark |
| --- | --- | --- | --- |
| 默认关闭 | 记录振铃、接通和结束 | 不下发任何来电控制命令 | 未接仍按原规则提醒 |
| 已开启的卡槽 | 记录上报。602 且 `telConnectedTs` 大于 0 时，Harbor 发送一次 `telstarttts` | 自动接听和录音来自事先下发的来电方式与上传地址。提示音由这一次 TCP 播放 | 录音关联到来电后发送「有留言」，不走未接或“曾来电”提醒 |
| 未选中的卡槽 | 与默认关闭相同 | 保持读回时的原值，接通后不发送 `telstarttts` | 未接规则不变 |

接通后的命令是 `telstarttts`：`p1` 为卡槽数字，`p2` 为应用接收设置里的提示语，`p3` 为 `1`（只播放一轮；缺省 0 会一直循环），`p5` 为 `0`（播完不挂断，线路留给来电者留言）。不发送 `p4`。同一通来电只发一次，键是卡槽、`telStartTs` 和 `telConnectedTs`。未接通的 601，以及 602 但接通时间为 0，或缺少开始时间，都不发送。命令若要等待其他板子操作，发送前会再核对原来电仍未结束，并且仍是该卡槽上开始时间最新的未结束来电。原来电已结束、被更晚的未结束来电代替、身份对不上或连接已换，就放弃这条提示音，不会顺延到下一通，也不会自动重试。发得太早时板子回 `code=200`「No call in progress」。

接受结果是 `type=401`、`subType=26`、`code=0`。不把 `type=402` 当成这条命令的成功，也不等待 687 / 689。失败不自动重发。`p5=1` 不用作留言结束条件。应用仍不发送 `telanswer`、`telstartrecord`、`teldial` 或 `telhangup`。

来电方式为模式 2 时，板子从接听就开始录音。提示音下行和来电者的留言可能进同一段 AMR。

## 网页播放

来电记录里的「播放留言」使用和管理下载相同的凭据，请求 `GET /api/calls/{id}/voicemail`。服务端仍返回原始 AMR，不在镜像里转码。页面在点击后加载 opencore-amr 的 WASM 解码器，得到 PCM，再交给 Web Audio 播放。同一时间只播放一条，离开来电页即停止。「下载 AMR」仍保存原始文件。

板子上传的是 AMR-NB（文件头 `#!AMR`），按 8000 Hz 单声道播放。现代 Chromium 和 Firefox 可以播放。`<audio>` 不能直接播放 AMR。页面的内容安全策略允许编译这段 WASM（`wasm-unsafe-eval`），不放宽脚本 `eval`。解码失败时下载仍然可用。

Safari 不作为这条能力的验收目标。没有 Web Audio 的浏览器会提示无法播放，下载不受影响。

## 未关联录音

“录音配置”页底部的“未关联录音”展示应用已保存、尚未对应到某次来电的录音。列表按保存顺序从新到旧排列，每页最多 50 条，可刷新和加载更早记录；展示上传卡槽、来电号码、通话开始时间、上传保存时间、文件名和大小。上传未提供的信息保留为“未提供”，不按当前 SIM 或接收时间补猜。

文件可读时，可直接播放或下载原始 AMR；权限与管理页面一致，不能仅凭上传令牌读取。应用接收开关关闭或当前为云端部署，也可查看该实例原有数据中的未关联录音，不因此开放新的云端上传。文件缺失、不可读或大小与索引不同会单独提示，并禁用播放和下载；数据库 ZIP 不含 AMR，恢复索引后仍需单独放回 `voicemail/`。

此模块只读，不修改关联、不发送通知，也不向板子发命令。自动关联规则保持原样：后续来电上报、重复上传或应用重启时重新尝试；关联成功后刷新列表，该录音不再出现在这里，改从对应来电查看。列表尚未刷新时点击已关联录音，会提示刷新。当前不提供手动关联或删除。

## 开启

能访问板子的 `/mgr` 时，也可手动配置来电应答和同一个录音上传地址，不必再执行重复的设置短信。手动设置不等于应用已经核实；无法通过 TCP 查询的项目仍需在板子后台确认。

1. 确认板子来电策略目前是“不接听”，录音地址为空。需要留言时再继续。
2. 在“录音配置”的第一步填写卡槽、提示语和局域网上传地址。页面可以填入模板；把 `192.168.31.x` 换成这台管理主机的局域网地址，并核对发布端口。
3. 勾选留言确认和保存确认，保存后重启应用。重启前运行中的进程仍按旧配置工作。
4. 在同页第二步读取板子设置。读取只走 TCP，不发短信。
5. 确认启用。上传地址用 TCP `setamrurl`。来电方式先试 TCP `slotcim` 模式 2；X32v158 拒绝时，改为从所选卡槽向该卡自己的号码发送 `*#slotNcim#`。启用不再写入 `slottts` 提示音预设，因此短信确认也不再为提示音发指令。其他卡槽不发指令。提示音留在 Harbor，等这张卡接通后再发 `telstarttts`。

上传地址必须是板子能访问的 HTTP，例如 `http://192.168.31.10:18880/api/voicemail/amr/<32位以上十六进制令牌>?slot={{slot}}&start={{telStartTs}}&phone={{phNum|$urlEncode()}}`。要求显式端口、IPv4 私网或本机地址，以及上述路径。公网域名、`nip.io` 和无端口地址不能保存。令牌由浏览器随机生成，不是管理凭据。

板子上传不带管理 Bearer。接口在留言已启用时，同时检查路径令牌和来源 IP 是否落在设备白名单。白名单关闭时拒绝上传。不要把该路径放到未校验来源的公开入口。

## 本地部署

现有 Compose 默认把网页发布在 `127.0.0.1`。板子访问不到这个地址。留言上传要在宿主把容器 `8080` 发布到局域网 IP 和端口，例如 `192.168.31.10:18880`。容器内部仍监听 `8080`。不要为了留言把默认绑定改成 `0.0.0.0`。云端服务器上的管理入口不能充当这块上传地址。

用覆盖文件增加局域网发布，并保留原来的项目名和数据卷。地址按这台主机的局域网网卡替换：

```yaml
services:
  sim:
    ports:
      - "192.168.31.10:18880:8080"
      - "192.168.31.10:39090:9000"
```

`setamrurl` 使用宿主局域网 IP 和发布端口，不是容器端口 `8080`，也不是 `127.0.0.1`。设备白名单写入板子自己的来源地址，例如 `192.168.31.20/32`，这样上传的来源就是板子。不要把上传再转给会改掉来源地址的反代，除非该反代保留板子地址并且不要求 Bearer。

升级前先备份数据库和 `system.private.json`，并单独复制数据目录里的 `voicemail/`。SQLite ZIP 含留言索引，不含 AMR 文件。只恢复 ZIP 不会把录音文件带回来。

v1.1.0 在首次启动时将数据库升级至 schema 19，留言保持关闭也会升级。schema 18 增加留言索引，schema 19 增加不含密码的控制短信账本。已发布的 v1.0.4 不能打开 schema 18 或 19。退回 v1.0.4 时使用升级前的备份，不要手改 `schema_version`。v1.0.4 的短信组装、持久去重和默认来电记录行为保持不变。

## 关闭并恢复

页面上的“已保存”表示下次重启将使用的设置，“当前生效”表示应用现在使用的设置。这两项都不代表板子已经停止接听。

1. 在“录音配置”取消应用接收并保存。这时只是已保存配置改为关。若还没重启，运行配置可能仍是开。页面会写明关闭应用开关不会自动停止板子接听。
2. 重启管理应用后，运行配置才关闭留言服务。新的来电不再按留言槽抑制未接提醒，应用也不再接收录音。板子自动接听不会因此撤销。
3. 在同页第二步重新读取，选择“停用：停止自动接听，清除板子预设提示语和上传地址”，核对预览后确认执行。预览列出目标卡槽、提示语和上传地址的修改，以及预计短信条数。需要发送设置短信时，单独确认停用和费用。短信已提交或被板子接受不等于设置已生效；显示“尚未确认停止自动接听”时，先重新读取，不要重复操作。

运行配置未选卡槽时，TCP 恢复会按读回的来电方式和提示音确定需要恢复的卡槽，并清空上传地址；即使只剩上传地址，也可以单独清空。短信通道无法完整读回来电参数，仍须在运行配置中指定卡槽。应用留言服务关闭不妨碍恢复板子；预览不可执行时，确认按钮不可用。

## 板子命令

厂家 TCP 目录里，录音地址是 `askamrurl`（子类型 56）和 `setamrurl`（子类型 55）。来电方式 `slotcim` 和提示音预设 `slottts` 只有短信指令，没有对应的 TCP 页面。接通后的提示音使用 TCP `telstarttts`，接受回执是 `type=401`、`subType=26`。X32v158 对 TCP `slotcim` 回 401 时，读取仍返回 `askamrurl` 的结果，来电方式标为 TCP 未返回，并且不因此中断查询，也不再接着查询 `slottts`。

确认启用时只写上传地址和来电方式。TCP `slotcim` 被拒绝时，应用从所选卡槽发出短信，收件号码填这张卡自己的号码：

- 来电方式：`*#slot2cim#用户密码#2`（接听并录音）或 `#0`（不接听）。不改响铃次数和最长通话。
- 启用不发送 `*#slotNtts#`。提示音里的 `#`、`@`、`&`、`~` 可以保留，因为接通后走 TCP JSON，不进短信正文。

若板子上还留着以前写入的 `slottts` 预设，接通时预设和 `telstarttts` 会各播一次。恢复会清空这个预设：TCP 能写时用 `slottts` 把文字置空；只能走短信时发送 `*#slot2tts#用户密码#`（密码后不带文字）。需要只保留 Harbor 的一轮提示音时，先恢复再启用。

用户密码在确认时输入，不写入配置、账本、发件记录或 Bark。带有指令格式的短信不进收件箱。出厂密码是 `000000`；改过则以板子为准。密码错误时板子 30 分钟内可能只回复一次。密码本身不能含 `#`、`@`、`&`、`~` 或空格。

短信指令会占用这条卡的短信，可能产生费用。读取不会发送。只对应用接收设置里选中的卡槽发，卡槽为空时不要选它。两张卡各自填写自己的本机号码，应用会分别和状态里的号码核对。

启用留言使用普通外发的限制：恢复保护未解除或外发未开启时不发送。停止自动接听要另勾确认；这时即使外发关闭或恢复保护还在，也只发送停止自动接听所需的短信，不会变成一条普通外发。

发送前把不含密码的记录写成“可能已发出”。控制短信和普通外发共用这张卡的发送间隔和每日限额。同一次确认里的下一条必要短信可以不受间隔限制，但每条仍占当日额度。账本按卡槽把还没被拒绝的控制记录连成一次操作。同一类指令重复同一目标时，如果这张卡槽之后没有新的未拒绝记录，就不再发送，结果未知或重启后也一样。中间做过另一次控制（例如恢复之后再启用）后，下一次恢复是新的操作：来电方式可以再改回不接听，清空提示音也可以再次发送，并且仍会清空上传地址。同一操作里已经记过的某一步不会让整次恢复失败，后面还没完成的步骤继续做；没有新记录时不会重发，也不会把跳过的步骤显示成已经确认。

X32v158 上，这条控制短信经常没有 type 501 回报（看不到「设置为来电」或「已经取消」）。板子仍然可能已经执行。Harbor 把缺少 501 记为已提交、待确认，不因此返回 502，也不把要下发的来电方式或提示音抄进读回结果。判定是：

- 尚未看到板子接受时，状态是已提交。
- 401 code 0 表示正在发送，402 表示命令已处理，502 / 503 是提交或送达类回执。这些只说明短信被接受，不说明来电方式已经改完。见到 402、502 或 503 后，最多再等大约一秒，以便收下已经在路上的 501。
- 若 501 真的到来，先核对来源号码、实际卡槽和可确认的 SIM 身份，并且短信时间不能早于这次发送。正文里写了“卡槽2”不够。对得上之后，正文符合本次指令才把对应参数标为已确认；正文是密码错误或格式错误则仍然失败。对不上的短信留在收件箱，不改变这次操作。早于这次发送的旧回复同样不能当成这次的结果。模式 2 的回复可能写成“N 声后自动挂断”，这是固件文案，应用只在本次下发的是模式 2 时把它当成接听并录音。
- 上传地址仍用 TCP 单独读回，和来电方式是否确认分开显示。

接通后是否自动接听，用打电话确认；提示音是否播放，看 Harbor 是否发出 `telstarttts`。再次点“读取”时，来电方式仍可能显示 TCP 未返回。这表示固件没有 TCP 查询，不表示刚才的短信失败，也不表示目标值已经生效。

只有和某次控制短信的卡槽、来源号码、可确认 SIM 身份都对得上，且短信时间不早于那次发送的回执，才不进收件箱。留言关闭、没有这笔账本，或其他号码、其他卡槽、换过的 SIM、缺少 SIM 身份或迟到的旧回复，包括正文里出现“设置为来电”，都照常保存和提醒。

录音优先按卡槽、开始时间和号码精确关联。时间差一点时，同号码的候选都保留，包括还没有卡身份的那一通。只剩一个候选且这通来电有卡身份才关联。不能先丢掉身份未知的来电，再把剩下的一条当成已经核对。号码写法可以带国家码。对不上、有多条候选、换过卡、没有卡身份或匿名来电时保持未关联，也不把“同卡槽最近一通”当成同一通。录音比来电先到、重复上传或应用重启后，用同样的规则再关联一次。文件只留一份，不重复来电通知；卡的静音和恢复后的通知保护保持原样。

## 核对

下面是可重复的产品核对，不依赖某一台机器或镜像标签。合成测试覆盖这些边界，但不能代替 v153 或其他固件的真机验收。板子外网保持阻断，上传只走局域网。

1. 留言关闭时打一通测试电话：只有来电记录和未接提醒，TCP 上没有接听、拒接、拨号或录音命令。收件箱仍保存普通短信。
2. 读取留言参数不会发送 `sendsms`，也不会改来电方式或提示音。
3. 启用前确认外发已开、恢复保护已解除，并勾选费用。号码必须是该卡当前的本机号码。启用确认里没有 `slottts` 或提示音短信。
4. 没有 501 时，页面写明短信已提交、来电方式尚未确认，并且不自动再发一次。有明确的模式回复时，才显示已确认。
5. 停止自动接听单独确认。外发关闭时这条停止短信仍可发出；启用留言则不能。
6. 向该卡槽打电话。板子自动接听后，Harbor 发送一次 `telstarttts`，提示音只播放一轮且不挂断，通话结束后 Harbor 收到 AMR。录音里可能混有这段提示音。
7. 来电记录可以播放或下载 AMR。播放走同一管理凭据，在浏览器里解码 AMR-NB；下载仍是原始文件。Bark 标题含「有留言」。同一录音重复上传不产生第二条通知。对不上的录音不挂到另一通来电上。
8. 未开启留言的另一卡槽仍只记录，不自动接听。
