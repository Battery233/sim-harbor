# 云端部署

在自己的 Linux 服务器运行同一套应用。板子仍使用家庭 WiFi，向云端独立 TCP 端口主动连接；管理网页通过 HTTPS 访问。

## 准备

- 一台可运行 Docker 和 Compose 的 Linux 服务器；镜像需为服务器实际架构构建。
- 一条可达的设备 TCP 入口，以及对应安全组/主机防火墙规则。
- 一个管理域名和 HTTPS 入口，可使用 [Cloudflare Tunnel + Access](cloudflare-setup.md)。

网页可以经 Tunnel 转发，板子的原生 TCP 不会自动进入网页路由。部署前阅读[设备通道安全边界](../SECURITY.md#设备通道)。

## 配置应用与入口

先按[Docker 安装](deployment-docker.md)生成私有文件，启动前修改：

| 位置 | 设置 |
| --- | --- |
| JSON `environment` | `cloud` |
| JSON `device_id` | 自己的设备编号 |
| JSON `public_url` | 如 `https://sim.example.com`，与管理入口一致 |
| JSON `device_cidrs` | 如 `["192.0.2.10/32"]`；这是示例保留地址，必须换为板子连接时的真实来源 |
| JSON `device_allowlist_enabled` | 保持 `true`，并与主机入口策略一致 |
| JSON `aes_mode` | 与板子匹配，示例 mode1；云端拒绝 mode0 |
| JSON `data_directory` | 全新实例保持 `/data`；迁移实例按恢复流程选择目标 |
| `.env` 的 `SIM_DEVICE_BIND` | 对外接入可设 `0.0.0.0`，配合来源限制 |
| `.env` 的 `SIM_DEVICE_PORT` | `39090`，或自选空闲高端口 |
| 宿主网页 | 保持 `127.0.0.1:18880`，由受保护的网页入口回源 |

云端直连通常看到家宽 NAT 出口 IP；若经过其他代理，以应用实际 TCP 对端地址为准。动态 IP 变化会使固定来源规则失效，需更新规则。关闭应用白名单会扩大连接范围，不能用网页 Token 弥补设备入口的保护缺口。

安全组和防火墙只开放所需设备端口与运维入口。高端口可避开已有服务冲突，但不构成认证或加密。配置中的 8080/9000 是容器内部端口，无需按宿主端口重写。

## 启动与网页发布

1. 按 Docker 文档构建并启动；先从服务器本机或 SSH 转发登录，确认应用健康。
2. 配置 HTTPS 管理入口。使用 Cloudflare 时，按[配置步骤](cloudflare-setup.md)设置域名、HTTP 回源和 Access。
3. 确认未认证访问会被拒绝或转到登录页，应用管理员 Token 仍保留；不要仅以 HTTP 200 判断访问控制成功。
4. 管理入口正常后，再按[板子配置指南](hardware-setup.md)核对网络、加密和上报事件，将目标设为 `tcp://自己的服务器地址:39090`，两端 AES 一致。
5. 按[首次接入顺序](../使用指南.md#首次接入顺序)确认双卡状态、自然短信、Bark 和详情链接。手机蜂窝网络应单独检查访问。

不要使用网页域名的 HTTPS 地址代替原生 TCP 目标，除非另有明确支持该板子的转发方案。应用健康、TCP 端口可达和板子成功上报是三个不同检查。

## 运维与迁移

重启、停服和升级见[Docker 安装](deployment-docker.md#5-重启停服与升级)，历史迁移见[数据维护](data-maintenance.md)。先停止旧实例继续接入，再将板子切到新实例，避免两个独立数据库产生分叉。

数据库备份不含私有运行配置。保留配置与凭据的独立私密副本；新实例的通知、公开地址和来源规则需分别核对。应用停止或服务器断网时，应用自身无法发出离线通知；需要外部可用性监测时应另行部署。
