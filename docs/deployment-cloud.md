# 云端部署

将 SIMHarbor 部署在自己的 Linux 服务器，随时通过 HTTPS 管理双卡。板子继续使用家中 WiFi，主动连接云端 TCP 入口；历史集中保存在自己的服务器，手机可从通知打开详情。

## 准备

- 一台可运行 Docker 和 Compose 的 Linux 服务器；镜像需为服务器实际架构构建。
- 一条可达的设备 TCP 入口，以及对应安全组/主机防火墙规则。
- 一个管理域名和 HTTPS 入口，可使用 [Cloudflare Tunnel + Access](cloudflare-setup.md)。

网页可通过 Tunnel 发布，设备则使用独立 TCP 入口。分别配置两条链路的访问策略，见[设备通道配置](../SECURITY.md#设备通道)。

留言默认关闭，不使用时无需配置上传入口。需要云端接收录音时，当前版本支持独立的 HTTPS 上传域名，经 Tunnel 或受控代理回源到应用 HTTP，按[公网录音接收](voicemail.md#公网录音接收)配置。管理域名继续使用 Access，录音入口不要求邮箱登录；不要直接把带登录验证的管理地址当作上传地址，也不为此暴露应用 HTTP 公网端口。

已有实例升级继续沿用板子 TCP 接入、设备来源规则、管理端 Access、端口和数据卷，不自动开启录音。v1.1.4 沿用 schema 21，从 v1.1.2 升级不新增迁移；更早受支持的数据库在首次启动时自动迁移，v1.1.1 及更早程序不能直接使用新库，具体备份与回退要求见[升级说明](releases.md#从-v113-升级到-v114)。

## 配置应用与入口

先按[Docker 安装](deployment-docker.md)生成私有文件，启动前修改：

| 位置 | 设置 |
| --- | --- |
| JSON `environment` | `cloud` |
| JSON `device_id` | 自己的设备编号 |
| JSON `public_url` | 如 `https://sim.example.com`，与管理入口一致 |
| JSON `device_cidrs` | 如 `["192.0.2.10/32"]`；这是示例保留地址，必须换为板子连接时的真实来源 |
| JSON `device_allowlist_enabled` | 保持 `true`，并与主机入口策略一致 |
| JSON `aes_mode` | 与板子匹配，推荐使用已验收的 mode1 |
| JSON `data_directory` | 全新实例保持 `/data`；迁移实例按恢复流程选择目标 |
| `.env` 的 `SIM_DEVICE_BIND` | 对外接入可设 `0.0.0.0`，配合来源限制 |
| `.env` 的 `SIM_DEVICE_PORT` | `39090`，或自选空闲高端口 |
| 宿主网页 | 保持 `127.0.0.1:18880`，由受保护的网页入口回源 |

云端直连通常看到家宽 NAT 出口 IP；经过其他代理时，以连接诊断中的实际 TCP 对端地址为准。使用动态家宽 IP 时，同步更新固定来源规则以保持连接。网页与设备各有独立的访问保护，配置方法见[安全说明](../SECURITY.md)。

按需开放设备端口与运维入口，可选择空闲高端口避开已有服务冲突，并配合来源规则。配置中的 8080/9000 是容器内部端口，宿主发布端口由 Compose 单独设置。

## 启动与网页发布

1. 按 Docker 文档构建并启动；先从服务器本机或 SSH 转发登录，确认应用健康。
2. 配置 HTTPS 管理入口。使用 Cloudflare 时，按[配置步骤](cloudflare-setup.md)设置域名、HTTP 回源和 Access。
3. 分别验证登录页、授权身份与未认证请求，确认访问控制生效，并保留应用管理员 Token。
4. 管理入口正常后，再按[板子配置指南](hardware-setup.md)核对网络、加密和上报事件，将目标设为 `tcp://自己的服务器地址:39090`，两端 AES 一致。
5. 按[首次接入顺序](../使用指南.md#首次接入顺序)确认双卡状态、自然短信、Bark 和详情链接。手机蜂窝网络应单独检查访问。

板子目标使用上表的 TCP 主机与端口，网页使用 HTTPS 管理域名。依次核对应用健康、TCP 可达和有效状态上报，即可逐层确认接入完成。

## 运维与迁移

网页系统配置保存后，可直接确认重启管理应用；端口和镜像变更通过 Compose 应用。重启、停服和升级见[Docker 安装](deployment-docker.md#5-重启停服与升级)，历史迁移见[数据维护](data-maintenance.md)。停止旧实例接入后，将板子切到新实例，由新实例接续保存记录。

数据库与私有运行配置分别备份；需要携带录音时，在数据库备份中勾选“同时备份通话录音”，并使用兼容格式 2 的工具恢复。迁移后核对通知、管理地址和来源规则，即可继续日常使用。需要监测服务器或应用自身的可用性时，可搭配外部监控。
