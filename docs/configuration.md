# 配置说明

本页说明应用端配置；WiFi、板子上报事件和来电策略等原厂设置见[板子配置指南](hardware-setup.md)。

## 文件与优先级

| 位置 | 用途 |
| --- | --- |
| `configs/*.example.json` | 不含真实凭据的示例 |
| `configs/container.private.json` | Docker 或自定义实例的初始化配置 |
| `.env` | Compose 端口、初始化凭据及配置路径 |
| 数据目录 `system.private.json` | 首次启动生成的完整私有配置，后续优先读取 |
| `deploy/site.private.yaml` | 实例镜像与可选端口覆盖 |

应用会先校验初始化配置，再加载固定数据目录内的 `system.private.json`。初始化文件及必需环境变量继续用于启动校验；首次运行后的配置变更以统一配置为准。

后续优先在“系统配置”保存通用业务参数和凭据；留言相关字段在“录音配置”保存，两页沿用同一份配置和版本冲突保护。保存后，再通过页面上的“确认重启应用”使其生效。凭据留空即可保留原值，清空 Bark 使用 Bark Key 输入框下方的专门选项；界面以配置状态展示凭据，保护密钥隐私。按卡通知开关单独即时保存。

数据目录、静态目录和运行环境通过部署配置管理。同一目录更新应用按[版本维护](releases.md)升级数据库；从备份创建实例按[恢复流程](data-maintenance.md)进行。首次选择新目录时可由初始化配置生成统一配置；移动已有目录时，初始化 JSON 与目录内 `system.private.json` 的 `data_directory` 必须指向同一路径。私有文件使用受限权限保存在自己的主机。

### 保存与生效

| 改动 | 生效方式 |
| --- | --- |
| 网页中的系统配置、Bark、外发开关等 | 保存后勾选重启确认，点击“确认重启应用” |
| 按卡通知开关 | 即时保存、生效 |
| `.env` 中的端口、镜像或容器环境变量 | 沿用原 Compose 项目与文件重新执行 `up -d` |
| 版本覆盖文件中的镜像 | 按[版本维护](releases.md)切换并核对运行版本 |

网页重启会重新加载应用配置，保留业务历史和已完成的迁移确认；设备连接随后重连。修改管理 Token 后，用新 Token 重新登录。

## 核心字段

| 字段 | 含义 |
| --- | --- |
| `environment` | `local` / `cloud`，为同一应用选择部署环境与对应校验 |
| `http_address` | 应用网页监听；容器中通常为 `0.0.0.0:8080` |
| `tcp_address` | 板子监听；容器中通常为 `0.0.0.0:9000` |
| `data_directory` | SQLite、统一配置、录音 `voicemail/`、备份 `backups/` 与日志所在目录；容器全新部署 `/data` |
| `static_directory` | 前端产物目录；容器 `/app/web/dist`，源码 `web/dist` |
| `backup_max_storage_mib` | 网页服务器备份 ZIP 总容量，缺省或 `0` 为 2048 MiB，显式范围 544～65536；最多 20 份，满后拒绝新增，不自动删除长期备份。保存并重启生效，见[备份管理](data-maintenance.md#中断清理与容量) |
| `device_id` | 允许接入的板子编号，配合来源规则与加密参数使用 |
| `device_cidrs` | TCP 来源网段，局域网录音上传也使用此规则；单 IPv4 用 `/32`，IPv6 用 `/128` |
| `device_allowlist_enabled` | 启用后按 `device_cidrs` 筛选 TCP 连接来源 |
| `aes_mode` | 两端一致，Key 与 IV 各 16 字节，见[安全说明](../SECURITY.md) |
| `public_url` | 手机能访问的管理入口；用于通知详情链接 |
| `admin_token_header` | v1.0.3 起支持；管理鉴权请求头名称，留空使用 `Authorization`，详见下方说明 |
| `skip_admin_token` | 默认 `false`；显式开启后，管理网页、API 和下载跳过面板 Token 校验，由既有外层认证保护；保存并重启生效 |
| `bark_base_url` | Bark 服务，例如 `https://api.day.app` |
| `device_timezone` | 板子时间解释与限额时区，默认 `Asia/Shanghai` |
| `stale_seconds` | 最近上报超过此时限视为不新鲜，示例 345 秒 |
| `incoming_text_escapes` | 可选的正文转义显示兼容；原文与导出保留原始内容 |
| `status_alerts_enabled` | 持续异常与恢复提醒，需 Bark 可用 |
| `voicemail_enabled` | 留言开关，默认关闭。开启需网页二次确认并重启；应用和板子选项集中在“录音配置”，板子参数另行确认下发。见[留言](voicemail.md) |
| `voicemail_slots` | 应用播放接通提示语、等待提醒及板子设置操作使用的卡槽，取 1 和/或 2；板子自动接听需另行配置，不随本字段自动改变 |
| `voicemail_tts` | 接通后由 Harbor 用 TCP `telstarttts` 播放一次的提示音，最长 274 个字符。启用确认不把这段文字写成板子预设 |
| `voicemail_amr_url` | 板子可访问的完整上传地址；路径令牌就是上传凭据，无单独令牌字段 |
| `voicemail_upload_mode` | v1.1.1-rc.4 起支持：缺省或 `lan` 为局域网 HTTP，`public` 为经受控代理的公网 HTTPS；独立于 `environment` |
| `voicemail_proxy_cidrs` | 公网模式允许的代理 IP，最多 16 个单 IP `/32` 或 `/128`，只接受私网或回环地址；缺省只信任 `127.0.0.1/32` 和 `::1/128`，显式填写后替代默认值 |
| `voicemail_max_storage_mib` | 公网录音目录容量上限，缺省 512 MiB，可设 16～65536；达到容量或 10000 条索引上限时拒收新文件，不自动清理；已配置 Bark 时，达到一半及其后每增加 32 MiB 提醒 |
| `outbound_enabled` | 短信外发开关，默认关闭；恢复保护优先 |
| `send_interval_seconds` | 每卡发送间隔，默认 60 秒，可配置 10～86400 秒 |
| `send_daily_limit` | 每卡每日尝试次数上限，默认 5 次，可配置 1～100 次 |
| `send_max_segments` | 单条短信的估算段数上限，默认 1 段，可配置 1～10 段 |

初始化环境变量名为 `SIM_ADMIN_TOKEN`、`SIM_AES_KEY`、`SIM_AES_IV`、`SIM_BARK_KEY`，JSON 通过对应 `*_env` 字段引用。管理员 Token 至少 24 字符；显式跳过面板凭据时可不配置 Token，已有值仍保留。标准 Compose 初始化仍要求 `SIM_ADMIN_TOKEN`，无需清空原值。

旧实例不要求补填留言字段；缺少 `voicemail_enabled` 时默认关闭，其他业务配置继续使用原值。各部署示例均显式关闭留言。公网接收需主动选择并配置，升级不会自动改变模式或板子设置。v1.1.8 沿用 schema 21；配置可沿用不表示数据库可直接降级，见[升级说明](releases.md#从-v117-升级到-v118)。

v1.1.1 的备份管理功能保持旧配置可读；设置非零 `backup_max_storage_mib` 后，回退到不认识该字段的旧程序前需从私有配置中移除该字段。正式版 1.1.1 的 ZIP 为格式 1、schema 20。v1.1.2 增加可选录音备份（格式 2）、共享播放状态及系统推送历史（schema 21）。旧配置无需补填；旧版不能直接打开 schema 21，格式 2 必须由支持该格式的新版维护工具校验恢复。不勾选录音时仍生成格式 1，但其中的数据库同样受 schema 兼容性限制。

### 自定义鉴权请求头

v1.0.3 起支持此配置，v1.0.2 尚不支持。默认请求格式为 `Authorization: Bearer <管理token>`。如果反向代理的 Basic Auth 也使用 `Authorization`，可在“系统配置 → 管理访问”将“自定义鉴权请求头”设为 `X-SIMHarbor-Authorization`，或在初始化 JSON 中设置：

```json
{
  "admin_token_header": "X-SIMHarbor-Authorization"
}
```

已有实例优先使用数据目录中的统一配置；后续应在网页保存，确认重启应用后生效，再刷新网页。只修改初始化 JSON 不会覆盖已保存的统一配置。此字段只填写头名称，管理 Token 不变；清空字段并保存、重启即可恢复默认头。

启用后，同一个请求可同时携带两层认证：

```http
Authorization: Basic <代理认证信息>
X-SIMHarbor-Authorization: Bearer <管理token>
```

反向代理需保留并透传自定义头，且 `/api/auth`、其余 `/api/` 路由和下载接口应使用同一代理入口。浏览器在发送管理凭据前读取 `GET /api/auth`；该接口仅返回当前生效的头名称与是否跳过面板凭据，不返回 Token、其他配置或业务数据，不绕过反向代理自身的认证。保存待重启的设置不会提前用于认证。

头名称不区分大小写，建议使用由英文字母和连字符组成的名称。应用拒绝空格、冒号、换行、超过 128 字符的名称，以及浏览器保留的 `Host`、`Cookie`、`Origin`、`Content-*`、`Sec-*`、`Proxy-*` 等字段。自定义后仅校验所选头，不同时回退接受 `Authorization`。请求头中的值仍须为 `Bearer <管理token>`；网页输入凭据时只填 Token 本身。

普通 API、导出、备份下载及容器健康检查使用同一配置。管理请求不跟随 HTTP 重定向；反向代理需直接返回 API 响应，不能将 API 重定向到其他地址。修改头名不改变凭据权限、同源校验或数据格式。

自定义鉴权请求头本身不引入数据库迁移。历史版本 v1.0.2 不识别该字段；准备旧版配置时应清空它，并确保初始化 JSON 也不包含 `admin_token_header`。清空后，统一配置不再写入该字段；凭据及其他配置保持原值。从当前版本回退还必须同时核对数据库和其他新增字段，不能仅清空请求头后换用旧镜像，见[版本维护](releases.md#回退)。

### 跳过面板凭据

已使用 Cloudflare Access 等统一认证时，在“系统配置 → 凭据”的管理访问凭据输入框下开启“跳过面板访问凭据”，保存并确认重启应用，再刷新网页。开关默认关闭，升级保留已保存的选择。开启后，通过外层登录即可进入管理台；管理 API、导出和文件下载使用同一访问策略，浏览器停止发送面板 Token。

外层认证覆盖管理域名的全站、`/api/` 和下载，宿主 HTTP 使用回环或受限网络监听；独立录音域名只路由完整上传路径。身份验证由外层完成，应用继续执行同源检查、上传令牌和来源校验，以及业务操作确认。

原 Token 保留，关闭开关并重启后恢复校验；从未配置过 Token 的实例需同时填写至少 24 字符的新值。回退到不识别 `skip_admin_token` 的旧版时，先恢复面板凭据校验，再从旧版使用的初始化与统一配置中移除该字段。关闭后重新保存的统一配置会省略此字段，数据库无需迁移。

外发限额按发送尝试记录计算，未知结果也计入。留言控制短信与普通外发共用同一张卡的间隔和每日额度。日期按 `device_timezone` 划分；实际值以当前配置为准。可根据套餐与使用习惯设置限额，详见[短信外发](features.md#短信外发)。

## 端口与来源

Docker 宿主端口由 `.env` 和 Compose 设置，容器监听由 JSON 设置。安装指南与 `deploy/.env.example` 推荐宿主 HTTP/TCP 为 `18880/39090`；容器内部仍为 `8080/9000`。基础 Compose 在未指定端口变量时回退到宿主 `8080/9000`，部署时沿用自己的 `.env` 即可。例如 `127.0.0.1:18880 → 8080` 与 `0.0.0.0:39090 → 9000` 可同时使用；后者是否可达还取决于防火墙和安全组。

设备来源规则依据原生 TCP 对端地址。设备规则与 Cloudflare 网页访问规则分别配置；可结合来源限制、传输模式和网络策略管理设备入口，见[安全说明](../SECURITY.md#设备通道)。

公网模式的代理地址与 TCP 白名单分别配置。应用检查实际 HTTP 对端，不依据 `X-Forwarded-For` 或 `CF-Connecting-IP` 放行；HTTPS 在代理入口终止，应用内部可以继续 HTTP。完整部署边界见[公网录音接收](voicemail.md#公网录音接收)。

## 日志保留

默认应用诊断最多 5000 条，磁盘日志保留 7 天，每文件最多 16 MiB、备份 3 份。达到保留容量时会限制新增磁盘记录，以控制空间占用。Compose 标准输出另按 2 MiB × 3 轮转。保留策略可在允许范围内配置；需长期归档的日志单独保存，业务备份集中保存数据库。
