# 板子配置指南

本指南面向通过家庭 WiFi 接入 sim 的双卡智能板，适用于[本地部署](deployment-local.md)与[云端部署](deployment-cloud.md)。以下为接入建议，不是所有型号的出厂默认值；菜单名称、参数单位及生效方式请结合实际固件和[厂家在线文档](reference/board/README.md)核对。

先完成应用安装，准备自己的设备编号、TCP 地址、AES Key/IV，再配置板子。首次接入保持应用短信外发关闭。已有正常运行的板子先读取现值，只修改与目标配置不一致的项目。

## 配置入口与准备

板子原厂管理页与 sim 网页是两个入口：WiFi、上报目标、事件开关和来电策略通常在原厂管理页配置；sim 的“系统配置”管理服务端参数、Bark 和访问凭据。

1. 按板子规格检查电源、天线、SIM 方向与卡槽；常见 X 系列使用 Type-C 5V、至少 2A 供电和 2.4GHz WiFi，其他型号以实物标识为准。
2. 完成配网，在路由器中确认板子的实际局域网地址。部分 X 系列固件的管理入口为 `http://板子IP/mgr`，不要把固定配网热点地址当作长期管理地址。
3. 修改原厂管理员密码；若另有普通用户密码，也分别修改。密码变化可能影响原厂接口 Token，私密保管新的访问资料。
4. 变更前将原厂配置导出到自己的私有存储。导出可能包含 WiFi、密码和 AES 密钥，不能公开分享，也不能替代应用数据库备份。

## 必需设置

| 设置项 | 建议配置 | 核对方式 |
| --- | --- | --- |
| WiFi | 连接稳定的家庭 WiFi；支持时使用路由器地址预留，避免板子或本地主机地址漂移 | 板子显示 WiFi 已连接，应用能收到有效上报 |
| 两卡蜂窝数据 / 备用联网 | 仅 WiFi 使用时，两槽均禁止蜂窝数据与数据回退 | 读取实际状态；不能仅因 WiFi 已连接就认定不会使用 SIM 流量 |
| TCP 上报目标 | 填应用主机实际可达的 `tcp://主机地址:设备端口`，参见下表 | 应用显示当前连接，并可查询新鲜状态 |
| 设备编号 | 服务端 `device_id` 与板子实际编号一致 | 不使用手机号、ICCID 或卡备注代替编号 |
| 通讯加密 | mode1（仅上行加密），Key/IV 与服务端一致，各 16 字节 | 两端核对模式后验证上报和状态查询；不要只凭“已连接”判断密钥正确 |
| 上报消息格式 | 保留厂家原生结构、标准字段名和必要字段，不套用第三方通知模板 | 收件与状态能被解析，见下方消息设置 |
| JSON 控制字符转义 | 固件提供相应选项时开启；部分界面称“JSON 控制字符转普通字符” | 带换行等内容的新短信能解析并正确显示；不是删除正文换行 |

禁止数据联网与关闭卡槽不是同一件事。保持两卡供电、注册及短信/语音所需能力，不因禁止数据而禁用整张卡或必要的漫游注册。不同固件对 `slotnet` 等选项的含义可能不同，不跨固件盲套原始命令；若没有独立 TCP 备用联网项，按实际联网设置和状态核对。

### 本地与云端的 TCP 目标

以下均为示例，需替换为自己的地址：

| 部署方式 | 板子上报目标示例 | 注意 |
| --- | --- | --- |
| 本地 Docker | `tcp://192.168.1.10:39090` | 使用应用主机的局域网地址和宿主发布端口 |
| 本地源码运行 | `tcp://192.168.1.10:39090` | 使用 JSON 中实际 TCP 监听的可达地址和端口 |
| 云端 Docker | `tcp://你的服务器地址:39090` | 使用独立设备 TCP 入口，核对安全组、主机防火墙和应用来源规则 |

不要填板子自身地址、`127.0.0.1`、`0.0.0.0`、Bark 地址或管理网页的 HTTPS URL。容器内部 `9000` 不一定是宿主发布端口。Cloudflare 网页路由不会自动代理板子的原生 TCP。

mode1 下发仍为明文，AES-CBC 不具备完整消息认证或防重放。mode2 不能只因界面或协议支持便认定实际固件兼容；不要为排障直接改成明文。设备入口保护见[安全说明](../SECURITY.md#设备通道)。

### 事件上报与消息字段

| 事件 | 设置建议 | 用途 |
| --- | --- | --- |
| `100`、`998` | 明确启用，不依赖“TCP 始终推送”的界面说明 | 握手与心跳 |
| `401`、`402` | 启用 | 命令反馈、状态与参数查询响应 |
| `501` | 启用 | 新短信上报 |
| `601`、`602`、`603` | 使用来电记录和未接提醒时启用 | 来电过程事件 |
| SIM 状态、模组错误等状态事件 | 建议保留 | 辅助判断注册、卡状态与异常 |
| `502`、`503` | 需要外发结果时保留；送达报告还依赖固件与运营商 | 提交和送达证据，开启上报本身不会发送短信 |

保留默认的设备、时间、事务、卡身份、长短信和来电字段，不随意添加别名或裁剪字段。不要将消息改包为第三方平台的 `text` / `content` 模板，也不要把 WiFi 密码、管理 Token 或 Bark Key 加进自定义上报参数。

如有关键词过滤，初次接入建议关闭，避免在板子端先丢弃部分短信。HTTP 的 GET/POST 和 Content-Type 选项不能替代 TCP 消息配置；TCP 模式下无需为了匹配网页 API 修改这些 HTTP 参数。

## 建议设置

| 设置项 | 建议值或做法 | 说明 |
| --- | --- | --- |
| 心跳间隔 | 可采用 110 秒，并与应用 `stale_seconds=345` 配合 | 约三个心跳周期加余量；已有稳定配置可保留，不是 110 秒发送一次短信 |
| 命令反馈超时 | 固件支持时可采用 8000 毫秒，即 8 秒 | 核对界面单位；板子上报超时不等于短信未发送，不自动重发 |
| 本地短信存储 | 两槽均开启 | 保留有限本地副本，满后可能覆盖；不等于断网后必定补报 |
| 本地通话记录存储 | 两槽均开启 | 便于人工核对，不代表自动接听或录音 |
| 来电处理 | 只需要未接提醒时，两槽均选择“不接听” | 固件支持时可设为响铃 3 声后不接听；接通后最大时长不等于自动接听等待时间 |
| 时间 / 时区 | 与应用 `device_timezone` 一致，例如 `Asia/Shanghai` 对应 UTC+8 | 核对新记录时间，不用错误时区抵消界面显示问题 |
| 录音 / 自动语音 | 不需要时关闭，录音上报地址留空 | 本项目不提供实时语音、录音管理或自动接听服务 |

原厂短信与通话存储开关可能只提供命令接口，也可能要求重启板子后生效。不要假定每个固件都有同名菜单；需要修改时先核对对应文档，安排一次明确的维护操作，完成后再读取配置并验证新记录。本项目网页目前只查询存储开关，不提供存储写入或板子重启按钮。

“不接听”不能约束运营商侧语音信箱、呼叫转移或资费；需要时自行核对套餐。仅待机或收到短信也不一定满足运营商保号条件。

## 可选设置与不必调整的项目

- **卡备注**：设置易辨认的名称，便于区分两卡；备注不能替代固定卡身份，改名不会重写历史名称。
- **定时重启**：不是接入前提。已有设置先核对，按自身可用性要求决定是否保留；不要为了完成安装统一启用每日重启或恢复出厂。
- **额外接口与自定义参数**：没有明确用途时保留默认，不增加重复上报目标，不把 Bark Key 配到设备上。Bark 由应用负责调用。
- **SIM 数据与自动化**：不默认开启蜂窝回退、自动拨号、自动短信、OTA 或定时收费动作。新增用途需另行评估资费、兼容性与恢复方式。

## 保存、生效与验收

逐项修改可能断连的设置，并保留原 TCP 目标和原厂管理入口。按照固件提示区分立即生效、需要重新连接和需要重启的设置；应用重启不会替代板子重启，页面保存成功也不等于运行状态已经改变。

完成设置后核对：

1. 应用能收到新鲜状态，WiFi 与两卡注册正常，实际数据联网策略符合预期。
2. 两卡各自自然收到新短信，应用记录的归属正确；有换行或长短信时再核对对应内容完整性。
3. 需要来电提醒时，检查普通未接来电记录；不要用自动拨号反复测试。
4. 在应用配置 Bark 和按卡开关，手机确认通知及详情地址；本地地址在蜂窝网络下通常不可达。
5. 有条件且能接受短暂中断时，另行验证 WiFi 中断、恢复和断电后的设置保留、重连与数据回退策略。单次正常状态不能证明全过程零流量或零费用。

应用“板子设置”可查询心跳、本地存储开关、最近状态及板子历史，心跳支持确认修改。WiFi、TCP 目标、加密和来电策略仍需在原厂界面或其正式配置接口处理；不要将本指南当作应用已经提供全部远程设置功能。
