# 板子配置指南

面向 **绿邮 X 系列双卡 4G 智能板**，已在 **v153 固件**上完成真机验收。本指南帮助板子通过家庭 WiFi 接入 SIMHarbor，适用于[本地部署](deployment-local.md)与[云端部署](deployment-cloud.md)。

下面整理了推荐配置与核对方法。菜单名称、参数单位及生效方式请结合实际固件和[厂家在线文档](reference/board/README.md)查看；接入其他型号或固件时，以对应协议与实测结果为准。

先安装应用，准备设备编号、TCP 地址及 AES Key/IV。已有稳定配置的板子可先读取现值，再按需调整；收件与状态接入完成后，再启用需要的外发功能。

## 配置入口与准备

原厂管理页负责 WiFi、上报目标、事件开关和来电策略；SIMHarbor 的“系统配置”负责应用参数、Bark 和访问凭据。

1. 按板子规格检查电源、天线、SIM 方向与卡槽。常见 X 系列使用 Type-C 5V、至少 2A 供电和 2.4GHz WiFi，具体以实物标识为准。
2. 完成配网，在路由器中确认板子当前局域网地址。部分 X 系列固件通过 `http://板子IP/mgr` 进入管理页。
3. 为原厂管理员和普通用户分别设置自己的密码，并私密保存更新后的访问资料；密码变化可能影响原厂接口 Token。
4. 将原厂配置导出到私有存储，方便恢复 WiFi、密码和加密参数。应用中的短信、来电与卡记录使用独立的[数据库备份](data-maintenance.md)。

## 接入配置

| 设置项 | 推荐配置 | 核对方式 |
| --- | --- | --- |
| WiFi | 稳定的家庭 WiFi；支持时在路由器预留地址 | 板子显示 WiFi 已连接，应用收到有效上报 |
| 两卡蜂窝数据 / 备用联网 | 以 WiFi 为主链路时关闭两槽蜂窝数据与数据回退 | 读取实际联网策略，同时保留两卡注册和短信/语音能力 |
| TCP 上报目标 | `tcp://应用主机地址:设备端口`，参见下表 | 应用显示当前连接，并可查询新鲜状态 |
| 设备编号 | 服务端 `device_id` 填写板子实际编号 | 与板子管理页中的设备编号核对 |
| 通讯加密 | mode1（上行加密），Key/IV 与服务端一致，各 16 字节 | 核对两端模式，验证有效上报和状态查询 |
| 上报消息格式 | 厂家原生结构、标准字段名及完整必要字段 | 收件与状态正常解析，消息设置见下文 |
| JSON 控制字符转义 | 固件提供相应选项时开启；部分界面称“JSON 控制字符转普通字符” | 新短信中的换行等内容能正常解析和显示 |

WiFi 数据策略与卡槽启用分别配置：使用 WiFi 联网时，保留两卡供电、网络注册及短信/语音能力。`slotnet` 等原厂选项的含义可按固件文档核对，再读取实际状态确认。

### 本地与云端的 TCP 目标

将示例替换为自己的地址：

| 部署方式 | 板子上报目标示例 | 地址选择 |
| --- | --- | --- |
| 本地 Docker | `tcp://192.168.1.10:39090` | 应用主机的局域网地址与宿主发布端口 |
| 本地源码运行 | `tcp://192.168.1.10:39090` | JSON 中实际 TCP 监听的可达地址与端口 |
| 云端 Docker | `tcp://你的服务器地址:39090` | 独立设备 TCP 入口，配合安全组、防火墙和应用来源规则 |

板子连接的是应用主机的设备 TCP 入口；管理网页使用单独的 HTTP/HTTPS 地址。Docker 示例把宿主 `39090` 映射到容器 `9000`。网页通过 Cloudflare 发布时，设备仍连接自己的 TCP 入口。

mode1 的传输行为为上行 AES-CBC 加密、下发明文，已用于本项目真机验收。设备入口的来源保护及其他模式说明集中在[安全说明](../SECURITY.md#设备通道)。

### 事件上报与消息字段

| 事件 | 推荐设置 | 用途 |
| --- | --- | --- |
| `100`、`998` | 显式启用 | 握手与心跳 |
| `401`、`402` | 启用 | 命令反馈、状态与参数查询响应 |
| `501` | 启用 | 新短信上报 |
| `601`、`602`、`603` | 使用来电记录和未接提醒时启用 | 来电过程事件 |
| SIM 状态、模组错误等状态事件 | 建议保留 | 判断注册、卡状态与异常 |
| `502`、`503` | 使用外发时保留 | 跟踪提交与送达报告；送达报告取决于固件及运营商支持 |

保留设备、时间、事务、卡身份、长短信和来电字段，使用厂家原生 TCP 消息结构。Bark 由应用统一发送，Key 保存在应用端。首次接入建议关闭关键词过滤，便于完整核对收件；TCP 模式使用原生消息配置，HTTP GET/POST 和 Content-Type 参数可保持原样。

## 日常运行建议

| 设置项 | 建议值或做法 | 使用收益 |
| --- | --- | --- |
| 心跳间隔 | 可采用 110 秒，配合应用 `stale_seconds=345`；已有稳定配置可保留 | 约三个心跳周期加余量，兼顾连接观察与频率 |
| 命令反馈超时 | 固件支持时可采用 8000 毫秒，即 8 秒，注意界面单位 | 给命令反馈留出响应时间，超时结果可在原任务继续核对 |
| 本地短信存储 | 两槽均开启 | 保存板子侧短信副本，便于人工核对 |
| 本地通话记录存储 | 两槽均开启 | 保存板子侧来电记录 |
| 来电处理 | 以未接提醒为主时，两槽选择“不接听” | 应用只记录来电；不要同时开启自动接听 |
| 时间 / 时区 | 与应用 `device_timezone` 一致，如 `Asia/Shanghai` 对应 UTC+8 | 短信、来电和限额时间保持一致 |
| 录音 / 自动语音 | 以短信和未接提醒为主时关闭，录音上报地址留空 | 需要留言时按[留言说明](voicemail.md)单独开启，并使用局域网上传地址 |

原厂存储开关可能通过命令接口配置，部分固件保存后需重启生效。按对应文档安排维护，并在生效后读取配置、核对新记录。SIMHarbor 的“数据维护”提供板子存储开关查询和历史查看，“运行诊断”中的板子心跳间隔支持确认修改；留言统一在“录音配置”管理。

板子本地存储可辅助核对，长期归档使用应用备份；断网后的补报行为以固件为准。语音信箱、呼叫转移、保号与漫游资费可结合自己的运营商套餐另行设置。

## 个性化配置

- **卡备注**：在原厂管理页为两张卡设置易辨认的名称。新记录展示新名称，旧历史保留当时的名称快照。
- **定时重启**：按自己的维护习惯选择；日常接入可以沿用已稳定运行的配置。
- **上报与通知**：板子负责原生 TCP 上报，应用集中管理 Bark 与按卡开关。
- **蜂窝回退与自动化**：有相应用途时，再结合套餐、固件能力和恢复方式单独规划。

## 保存与验收

保留原 TCP 目标及管理入口，逐项保存可能影响连接的设置。按固件提示区分立即生效、重新连接及板子重启；完成后以实际运行状态读回核对。

1. 在首页查询新鲜状态，确认 WiFi、两卡注册与数据联网策略。
2. 两卡各接收一条自然到达的新短信，核对归属与内容；遇到长短信或换行时检查完整显示。
3. 如需来电提醒，确认测试目标及资费后检查普通未接来电记录。
4. 配置 Bark 和按卡开关，在手机确认通知及详情链接；需要外出访问时核对蜂窝网络可达性。
5. 安排可接受的维护窗口，观察网络中断与断电后的重连、配置保留和数据回退行为。

完成后即可用应用查看状态、收件、来电和通知。后续调整 WiFi、TCP 目标、加密或来电策略时，沿用原厂配置入口与上述核对流程。
