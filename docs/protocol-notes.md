# 协议说明

设备通过原生 TCP 完成上报、状态查询和命令响应，本地与云端共用协议路径。X 系列 v153 固件已完成真机验收，协议字段与其他型号接入可参考[厂家在线文档](reference/board/README.md)。

## 帧与状态

实现处理 TCP 分段/合并、帧解析、设备标识、事务关联及超时。有效帧经过业务校验再持久化；日志使用摘要与失败类别帮助定位问题，并保护载荷和凭据隐私。

状态查询使用有效会话及新鲜度判断。卡身份以有效 ICCID 关联固定 ID，卡槽只是当前物理位置；缺失身份时明确标为未知。事件时间按配置时区解释，设备事件时间与应用接收时间分别处理。

## 短信与来电

收件解析会保留原始正文语义、长短信分片与完成状态，并去重持久化；通知只在满足完整性条件后创建。显示转义选项不改变保存的原文。

长短信额外保存总片数和匿名组引用，同一业务记录后续报告的总片数必须与已保存的非零总数一致，冲突事件回滚并保留已有分片。升级旧库不会根据正文或已有分片猜测总数；后续匹配上报可提供总数，但应用无法核对升级前未保存的总数是否曾与其不同。

默认信息级别日志记录成功解析并通过设备标识检查的长短信上报：匿名组引用、短信时间、总片数、本次分片序号、板子完整标记，以及入库事务结果；日志时间为应用实际接收/处理时间。没有组或分片信息的普通完整短信不记为长短信；缺少组号但明确报告未完整的事件仍记录诊断。成功入库后可读回记录编号和完整状态，诊断读回失败不影响业务结果。解密或结构解析失败仍记录通用错误类别，不输出原始报文。日志不含正文、号码、原始组号、设备或 SIM 身份。

匿名组引用用于关联同卡、同发送方、同组号的上报，不包含短信时间，便于发现时间变化；它不改变业务分组及去重规则。组号可能复用，同一引用不是永久唯一的短信编号，需结合短信时间与应用处理时间核对。运行诊断可按该摘要筛选，日志保留范围见[配置说明](configuration.md#日志保留)。

业务组装键仍包含短信时间，同组号但不同时间的记录不会仅凭匿名引用合并。缺少组号时不自动拼接分片，也不据此认定完整；同组总数冲突或未完整记录中的分片内容冲突会回滚本次事件。入库错误沿用既有连接处理规则，关闭当前 TCP 连接，等待板子重新连接；应用不主动请求重传或查询板子历史。

来电开始、结束、接通和冲突信息分别处理，结束信息待定时以明确标注的提醒帮助核对。板子本地历史独立查询，应用长期历史通过业务库与一致备份管理。

## 命令与结果

管理操作采用明确的命令集合、串行查询与事务关联。参数写入经过读取、确认和读回；连接中断后保留待核对结果，按原事务查询，避免重复写入。

短信外发的板子接受/处理、运营商提交和送达报告分别保存；401/402 不能证明送达，502 表示提交，503 需要唯一关联及所有分片成功才可判断相应报告。回执关联不明确时保留歧义，不按猜测认定成功。

## 加密兼容

支持配置 mode0/1/2。mode1 上行加密、下行明文，已用于真机验收；mode2 按实际固件核对双向加密兼容性。云端配置要求加密模式，本机测试可用 mode0。两端 Key/IV 与模式保持一致，再通过有效状态上报验证。

AES-CBC 不提供完整认证或防重放，设备编号不是密钥。详见[安全说明](../SECURITY.md)。
