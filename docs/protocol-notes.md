# 协议说明

设备使用原生 TCP 与同一个应用通信，管理操作不依赖另建局域网 HTTP 控制模块。协议字段和型号能力应对照[厂家在线文档](reference/board/README.md)及实际固件核对；仓库不分发厂商原文或示例凭据。

## 帧与状态

实现处理 TCP 分段/合并、帧解析、设备标识、事务关联及超时。异常帧不会直接视为有效业务。日志记录摘要和失败类别，不应保存完整载荷或凭据。

状态查询使用有效会话及新鲜度判断。卡身份以有效 ICCID 关联固定 ID，卡槽只是当前物理位置；缺失身份不猜测历史卡归属。事件时间按配置时区解释，不能把接收时间自动等同实际发生时间。

## 短信与来电

收件解析会保留原始正文语义、长短信分片与完成状态，并去重持久化；通知只在满足完整性条件后创建。显示转义选项不改变保存的原文。

来电开始、结束、接通和冲突信息分别处理，缺少结束时仅作明确标注的保守兜底。板子本地历史查询不导入业务库、不等同补报队列或完整备份。

## 命令与结果

管理操作使用受限命令、串行查询与事务关联，不提供任意指令入口。参数写入要求先读、确认和读回；失联后保留未知，不自动重复写入。

短信外发的板子接受/处理、运营商提交和送达报告分别保存；401/402 不能证明送达，502 表示提交，503 需要唯一关联及所有分片成功才可判断相应报告。回执关联不明确时保留歧义，不按猜测认定成功。

## 加密兼容

支持配置 mode0/1/2，云端禁止 mode0。mode1 上行加密、下行明文；mode2 仍需固件验证，不能只因可选便宣称所有板子兼容。Key/IV 两端需一致，模式不匹配可能表现为 TCP 已连接但无有效业务。

AES-CBC 不提供完整认证或防重放，设备编号不是密钥。详见[安全说明](../SECURITY.md)。
